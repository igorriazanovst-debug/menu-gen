# DEPLOY: релизная сборка Android (RuStore)

Отладочный APK собирается на каждый push (`flutter_ci.yml`). Магазинная сборка —
отдельный workflow `android_release.yml`, запускается руками и требует ключа
подписи.

## Что зафиксировано навсегда

| Что | Значение | Почему нельзя менять |
|---|---|---|
| `applicationId` | `ru.menugen.app` | У опубликованного приложения не меняется. Другой id — другое приложение, без обновлений для установивших |
| Ключ подписи | `menugen.jks` | Подпись опубликованного приложения сменить нельзя. Потерял ключ — не выпустишь обновление |

**После смены `applicationId` установленные отладочные сборки становятся
отдельным приложением.** На тестовых устройствах будут две иконки MenuGen —
старую (`com.example.menugen_app`) надо удалить руками.

## Шаг 1. Создать keystore (один раз)

На своей машине, не на сервере и не в репозитории:

```bash
keytool -genkey -v \
  -keystore menugen.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias menugen
```

Спросит пароль хранилища, потом данные владельца (имя, организация, город,
страна — можно свои), потом пароль ключа. **Пароли запиши сразу**, восстановить
их нельзя.

Срок 10000 дней (~27 лет) — так и надо: истёкшим ключом обновление не подписать.

### Куда положить копии

Ключ и пароли нужны для каждого будущего обновления. Потеря = приложение
в магазине становится «замороженным»: обновить его не сможет никто, включая
тебя. Минимум две копии в разных местах (менеджер паролей, зашифрованный
архив), и ни одной — в репозитории.

Проверить, что ключ рабочий:

```bash
keytool -list -v -keystore menugen.jks -alias menugen
```

Выведет отпечатки SHA-1 и SHA-256. **SHA-256 сохрани отдельно** — он понадобится
для App Links (`assetlinks.json`), когда будем делать открытие ссылок из писем
прямо в приложении.

## Шаг 2. Положить ключ в секреты GitHub

Ключ — двоичный файл, в секрет он кладётся в base64:

```bash
base64 -w0 menugen.jks > menugen.jks.base64   # macOS: base64 -i menugen.jks -o menugen.jks.base64
```

Дальше **Settings → Secrets and variables → Actions → New repository secret**,
четыре секрета:

| Имя секрета | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | содержимое `menugen.jks.base64` целиком, одной строкой |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища (первый, который спрашивал keytool) |
| `ANDROID_KEY_ALIAS` | `menugen` |
| `ANDROID_KEY_PASSWORD` | пароль ключа (второй; часто совпадает с первым) |

Файл `menugen.jks.base64` после этого удали — он не нужен и это тот же ключ
в открытом виде:

```bash
rm menugen.jks.base64
```

## Шаг 3. Собрать

**Actions → Android Release → Run workflow**. Поля:

- **Адрес API** — оставить `https://menugen.ru/api/v1`;
- **Версия** — например `1.0.0`; пусто — возьмётся из `pubspec.yaml`;
- **Что собрать** — `apk+aab` (RuStore принимает и то, и другое; лишний формат
  под рукой избавляет от повторной сборки, если попросят другой).

Номер сборки (`versionCode`) подставляется из номера запуска workflow — он
всегда растёт, поэтому «версия уже загружена» при повторной подаче не случится.

Готовые файлы — в артефактах запуска: `menugen-release-<номер>-<коммит>.apk`
и `.aab`.

### Что workflow проверяет до сборки

- адрес API — только `https` и не локальный: релиз с адресом эмулятора внешне
  не отличим от рабочего, а обнаружится это уже у пользователей магазина;
- наличие секрета с ключом — иначе Gradle молча подписал бы сборку отладочным
  ключом;
- после сборки — что подпись действительно не отладочная (`apksigner`).

## Шаг 4. Проверить APK на устройстве

Скачай APK из артефактов и поставь на телефон, **удалив прежнюю отладочную
сборку**. Проверь:

- вход под существующим аккаунтом;
- регистрацию нового (письмо приходит, ссылка работает);
- генерацию меню;
- оплату подписки: выбор периода, переход в браузер, возврат в приложение.

Про оплату отдельно: релиз ходит на `https://menugen.ru`, а не на дев-сервер.
Аккаунты у них разные — пароль от дева не подойдёт.

## Шаг 5. Загрузить в RuStore

Понадобится, кроме файла:

- аккаунт разработчика (VK ID); **для монетизации с 01.02.2026 нужен ИП или
  юрлицо** — самозанятым платёжные инструменты RuStore недоступны;
- описание, скриншоты, иконка 512×512, категория, возрастной рейтинг;
- ссылка на политику конфиденциальности: `https://menugen.ru/privacy`;
- **тестовый аккаунт для модератора** — с подтверждённым e-mail и активным
  премиумом (выдать промокодом). Без него модератор увидит только экран входа
  и половину приложения, закрытую подпиской;
- пояснение, зачем приложению камера: распознавание продуктов и фото товаров
  в списке покупок.

### Шаг 5а. Подпись при загрузке AAB

Касается только формата AAB. **С APK делать ничего не нужно**: он уже подписан
нашим ключом целиком и попадает на устройство ровно таким, каким вышел
из сборки.

AAB — не готовое приложение, а заготовка: устанавливаемые APK магазин собирает
из неё сам, под конкретное устройство. Собранное магазином надо чем-то
подписать — поэтому при первой загрузке AAB RuStore просит **ключ подписи
приложения**. Ключ передаётся зашифрованным (утилита `pepk`), хранится
на их стороне и используется только для подписи этих APK.

**Ключ обязан быть тем же самым `menugen.jks`.** Если отдать RuStore другой
ключ, приложение из магазина окажется подписано не так, как APK, который уже
стоит у тебя и у тестировщиков: обновление поверх него не встанет, Android
отвергнет установку с «signatures do not match». Своего ключа RuStore
не создаёт и потерянный не восстановит.

Порядок:

1. В консоли RuStore, в разделе загрузки версии, выбрать AAB. Консоль покажет
   **ключ шифрования** (длинная строка) и даст скачать **`pepk.jar`**.
2. Зашифровать наш ключ этой утилитой. Java берём из Android Studio — отдельно
   ставить JDK не нужно. В PowerShell:

   ```powershell
   & "C:\Program Files\Android\Android Studio\jbr\bin\java.exe" -jar pepk.jar `
     --keystore=C:\keys\menugen.jks `
     --alias=menugen `
     --output=C:\keys\pepk_out.zip `
     --encryptionkey=СТРОКА_ИЗ_КОНСОЛИ `
     --include-cert
   ```

   Спросит пароль хранилища, затем пароль ключа — у нас они совпадают.
   На выходе `pepk_out.zip`; в нём ключ, зашифрованный публичным ключом
   RuStore, — прочитать его может только магазин.
3. Отдельно выгрузить **сертификат загрузки** — открытую часть того же ключа:

   ```powershell
   & "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -export -rfc `
     -keystore C:\keys\menugen.jks -alias menugen -file C:\keys\upload_certificate.pem
   ```

   Пароля хранилища достаточно, секрета в этом файле нет.
4. Загрузить в консоль `pepk_out.zip` (подпись приложения) и
   `upload_certificate.pem` (сертификат загрузки), затем сам `.aab`
   из артефактов сборки.

Дальше система проверит автоматически: подпись, `targetSdkVersion`, наличие
64-битных библиотек и совпадение `applicationId` с карточкой. У нас всё это
в порядке: `targetSdk 34`, `arm64-v8a` в сборке, id `ru.menugen.app`.

`pepk_out.zip` после загрузки можно удалить — он одноразовый. **`menugen.jks`
удалять нельзя никогда**: им подписывается каждый следующий AAB, и без него
обновление не выпустить.

### Стоит ли вообще переходить на AAB

Не обязательно. RuStore принимает и APK — тот, что уже собирается workflow.
Разница: AAB даёт пользователю скачивание меньше на треть (в APK лежат все
архитектуры сразу), но требует отдать ключ магазину и добавляет шаг к каждой
подаче. Пока приложение одно и на модерации — проще остаться на APK
и перейти на AAB, когда размер начнёт мешать.

### Про оплату мимо RuStore

Подписка продаётся на сайте через ЮKassa, из приложения открывается браузер.
По документации RuStore это допустимо: монетизация вне их платёжных SDK
разрешена, комиссию за неё RuStore не берёт (в отличие от Google Play, где
Play Billing для цифровых товаров обязателен).

Перед первой подачей стоит получить письменное подтверждение от поддержки
RuStore — вопрос на одно сообщение, а отказ на модерации после сборки стоит
дороже.

## Локальная сборка релиза (если понадобится)

Создать `android/key.properties` (он в `.gitignore`):

```properties
storeFile=/абсолютный/путь/menugen.jks
storePassword=...
keyAlias=menugen
keyPassword=...
```

Затем:

```bash
cd mobile/menugen_app
flutter build apk --release \
  --dart-define=API_BASE_URL=https://menugen.ru/api/v1 \
  --build-name=1.0.0 --build-number=2
```

Без `key.properties` сборка не упадёт, но подпишется **отладочным** ключом —
для магазина она не годится. Проверить:

```bash
apksigner verify --print-certs build/app/outputs/flutter-apk/app-release.apk
```

`CN=Android Debug` в выводе — сборка отладочная.

## Что осталось на потом

- **targetSdk 34.** Для RuStore сейчас хватает; Google Play требует 35, и
  переход включает принудительный edge-to-edge на Android 15 — нужна отдельная
  проверка вёрстки.
- **Сжатие кода (R8).** Уменьшает размер, но ломается только в релизе и только
  в рантайме. Включать после того, как обычная релизная сборка проверена.
- **App Links.** Ссылка подтверждения e-mail будет открывать приложение
  напрямую. Нужен SHA-256 отпечаток ключа (шаг 1) и `assetlinks.json` на домене.
